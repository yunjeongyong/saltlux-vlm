## 2. 같은 모델인데 왜 점수가 다른가

`alt/high 0.9032` 와 `exp_004 0.8956` 은 **같은 가중치를 서로 다른 시스템에 태운 결과**입니다.
차이를 만드는 층이 셋이고, 각각 실제로 재봤습니다.

### (1) 서빙 엔진 — vLLM vs transformers

같은 가중치 · 같은 프롬프트 · 같은 greedy 로 receipt 100건을 양쪽에서 뽑아 비교했습니다.

| 항목 | 값 |
|---|---|
| 평균 CER (엔진 vs 로컬) | **0.1072** |
| 완전일치 | 25 / 100 |
| 사실상 동일 (CER < 0.02) | **53 / 100** |
| 크게 갈림 (CER > 0.20) | **15 / 100** |

엔진 자체는 결정적입니다 — 같은 입력을 3회 호출해 md5 가 모두 같았습니다.
그런데도 로컬과 갈리는 이유는 **MoE 구조** 때문입니다.
Qwen3.6-35B-A3B 는 토큰마다 전문가 256개 중 8개를 고릅니다.
커널 구현이 다르면 라우팅 점수에 미세한 수치 차가 생기고, 그게 전문가 선택을 한 번 뒤집는 순간
그 다음 토큰부터 출력이 통째로 갈라집니다.
실제로 receipt41 은 엔진에서 `주문번호: 0000000…` 반복 루프가 났고 로컬에서는 정상이었습니다.

> **같은 가중치라도 서빙 스택이 다르면 점수가 달라집니다. 이게 첫 번째 원인입니다.**

### (2) 파이프라인 — 영역 분할 vs 페이지 통짜

| | Document Studio | 저희 측정 |
|---|---|---|
| 레이아웃 검출 | PP-DocLayoutV3 로 영역 분할 | 없음 |
| VLM 호출 | 영역마다 1회 (문서당 N회) | 페이지당 1회 |
| 프롬프트 | 영역 종류별 전용 (ocr / table / chart / seal …) | 문서 종류별 1종 |
| 조립 | 영역 결과를 좌표 순으로 재조립 | 모델 출력 그대로 |

같은 exp_004 가중치로 뽑은 두 출력의 일치도는 **본문 CER 0.42 / 표 TEDS 0.49** 입니다.
즉 **절반 이상이 다른 텍스트**입니다. 모델이 같아도 제품 출력은 같을 수 없습니다.

### (3) 디코딩 — 샘플링 vs greedy

DocStudio 워커는 temperature/top_p/top_k 를 지정하지 않아 vLLM 기본값(샘플링)으로 돕니다.
저희 측정은 greedy 입니다. 같은 모델도 매 호출 결과가 달라집니다.

### 정리

alt/high 행은 **"exp_004 가중치를 쓴 Document Studio 제품 전체"** 의 점수이고,
exp_004 행은 **"그 가중치만 떼어 VLM 단독으로 돌린"** 점수입니다.
두 숫자의 0.0076 차이는 모델 차이가 아니라 **전처리·조립·디코딩이 만든 차이**입니다.

## 3. SS 400건 — Document Studio 기준선과의 일치도

SS 평가셋에는 사람이 만든 파싱 정답이 없습니다. `data/<type>/jsons` 는 Document Studio API 응답입니다.
따라서 아래 CER/TEDS 는 **정확도가 아니라 "DocStudio 와 얼마나 같은가"** 로 읽어야 합니다.
표 스타일 속성이 CER 을 지배해서 본문과 표를 분리해 쟀습니다.

| 도메인 | 출력 | n | 본문 CER↓ | 표 TEDS↑ |
|---|---|---|---|---|
| receipt | exp_004 엔진(vLLM) | 98 | 0.4241 | 0.4861 |
| receipt | exp_004 로컬 | 98 | 0.4047 | 0.4526 |
| receipt | **exp_009 로컬** | 98 | **0.3549** | **0.6028** |
| receipt | 학습 전 base | 51 | 0.7991 | **0.0000** |
| quotation | exp_004 엔진(vLLM) | 100 | 0.6500 | 0.3955 |
| quotation | **exp_009 로컬** | 100 | **0.5876** | **0.4644** |
| invoice | **exp_004 엔진(vLLM)** | 100 | **0.3442** | **0.4577** |
| invoice | exp_009 로컬 | 100 | 0.4215 | 0.4025 |
| bill | **exp_004 엔진(vLLM)** | 100 | **0.1904** | **0.4776** |

**읽는 법**

- **학습 전 base 의 표 TEDS 가 0.0000** 입니다. 원본 모델은 표를 HTML 로 아예 못 뱉습니다.
  학습으로 얻은 것이 가장 뚜렷하게 보이는 지점입니다.
- receipt·quotation 은 exp_009 가, invoice·bill 은 exp_004 가 DocStudio 에 더 가깝습니다.
  다만 exp_009 쪽은 **로컬(transformers)** 이고 exp_004 쪽은 **엔진(vLLM)** 이라 조건이 다릅니다.
  **exp_009 도 엔진으로 돌려야 공정한 비교가 됩니다** (4-2 항).

## 5. 내부 보고용 — CER / TEDS (자체 평가셋 1,019 크롭)

이쪽은 **사람이 만든 정답이 있어 진짜 정확도**입니다. 유계 CER(0~1)로 통일했습니다.

| 모델 | CER↓ | TEDS↑ | 완전일치↑ | 반복루프 | 표 파싱실패 |
|---|---|---|---|---|---|
| 학습 전 base | 0.1378 | 0.6647 | 57.9% | 0 | 10 |
| exp_003 | 0.1302 | 0.7287 | 57.2% | 1 | 1 |
| **exp_004 (현 배포)** | **0.1063** | 0.7079 | **64.2%** | 7 | 6 |
| exp_005 | 0.1081 | 0.6831 | 65.3% | 1 | 9 |
| exp_006 | 0.1177 | 0.6916 | 64.4% | 0 | 3 |
| exp_007 | 0.1155 | 0.6691 | 63.1% | 0 | 5 |
| exp_008 | 0.1305 | 0.6879 | 60.8% | 0 | 5 |
| exp_009 ck14000 | 0.1176 | 0.7464 | 63.0% | 1 | 1 |
| **exp_009 최종 (24,646 step)** | 0.1155 | **0.7476** | 63.5% | **0** | 3 |
| **1차 목표** | **≤ 0.097** | **≥ 0.739** | **≥ 67%** | | |

- **TEDS 는 목표를 넘겼습니다** (0.7476 ≥ 0.739). 표 파싱이 1차 목표선에 도달했습니다.
- CER 0.1155 는 목표 0.097 대비 미달이고, exp_004(0.1063)보다도 높습니다.
- **반복루프가 exp_004 7건 → exp_009 0건**으로 사라졌습니다. exp_004 의 CER 이 낮게 나온 것과
  별개로, 반복루프는 운영에서 가장 위험한 실패 유형입니다.
- 표 파싱 실패는 base 10건 → exp_009 3건.

**해석** — exp_009 는 표(TEDS +0.040) 와 안정성(반복루프 7→0)을 얻고 텍스트 CER 을 조금 내줬습니다.
SS receipt KIE 에서 exp_009 가 exp_004 를 앞선 것(0.8981 vs 0.8956)은 이 교환이
실제 문서에서는 이득이었다는 뜻으로 보입니다. 다만 100건 표본이라 300건이 나와야 확정됩니다.
