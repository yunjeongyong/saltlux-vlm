## 1. 구조 — Document Studio 와 우리 모델의 관계

Document Studio 는 파싱 제품이고, **실제로 글자를 읽는 것은 그 안의 VLM 엔진**입니다.
워커는 레이아웃을 검출해 영역을 자르고 결과를 조립할 뿐, 모델을 갖고 있지 않습니다.

```
이미지 ─→ 워커(Document Studio) ─┬─ 영역별 프롬프트 ─→ VLM 엔진 ─┐
                                 │        (문서당 N회 호출)      ├─ 좌표순 재조립 ─→ 마크다운
                                 └──────────────────────────────┘
                                                ↑
                                     우리가 학습한 모델이 여기 들어감
```

52번 서버 현재 구성입니다.

| 포트 | 역할 | 내용 |
|---|---|---|
| `:60150` | 엔진 A (GPU7) | exp_004 병합 모델 |
| `:60151` | 엔진 B (GPU5) | exp_009 병합 모델 |
| `:12000` | 워커 1 | 엔진 A 호출 — **이것이 alt/high 경로** |
| `:12200` | 워커 2 | 엔진 B 호출 — 오늘 신규 기동 |

두 엔진은 **같은 도커 이미지·같은 vLLM 커밋**(`0.20.1.dev0+g88d34c640.d20260506`)이고
`--max-model-len 32768 --gpu_memory_utilization 0.95 --max-num-seqs 192` 로 동일합니다.
양자화는 하지 않았고 bf16 원본입니다(`quantization_config: None`).

## 2. 정정 — 심판(KIE 추출기) 인스턴스가 섞였습니다

### 무엇이 문제였나

KIE 채점은 파싱된 마크다운에서 필드를 뽑는 별도 LLM(심판)이 수행합니다.
강한빛 선임 기준선은 선임 엔드포인트로, 저희 측정은 52번 서버 gemma(`localhost:14006`)로
채점됐습니다. **같은 `gemma-4-31B-it` 이지만 인스턴스가 다릅니다.**

같은 파싱(`test_output_alt/parsing`)을 두 심판으로 채점한 결과입니다.

| 도메인 | 강한빛 선임 심판 | 저희 심판 | 차이 |
|---|---|---|---|
| receipt | 0.902 | 0.935 | **+0.033** |
| quotation | 0.870 | 0.904 | **+0.034** |
| invoice | 0.801 | 0.811 | +0.010 |
| bill | 0.866 | 0.868 | **+0.002** |
| **전체** | **0.860** | **0.880** | **+0.020** |

**보정폭이 +0.002 ~ +0.034 로 제각각이라 상수 보정이 불가능합니다.**
비교하려던 차이(exp_009 0.867 vs alt 0.860 = 0.007)보다 심판이 만드는 폭(0.020)이 커서,
두 값을 나란히 놓을 수 없었습니다.

### 정정 내용

| 항목 | 앞서 보고 | 정정 |

| receipt · DocStudio + exp_009 | 0.905 | 0.905 |

**부호가 반대입니다.** 앞서 드린 "exp_009 가 exp_004 를 넘었다"는 결론을 철회합니다.

## 5. 프롬프트 — 저희가 손대지 않았습니다

| 층 | 프롬프트 | 소유 |
|---|---|---|
| 파싱 | `prompts/high.json` (`ocr`/`table`/…) | **Document Studio 제품** |
| KIE 추출 | `kie_label.py` 의 `PROMPTS`/`SCHEMAS` | **강한빛 선임** |
| 단독 측정 | 한 문장 (학습 시와 동일) | 저희 |

`DocStudio + exp_009` 수치는 **제품 프롬프트를 그대로 받았을 때 모델이 낸 결과**입니다.
프롬프트 튜닝으로 만든 숫자가 아닙니다.

참고 — 파트장님이 주신 `high.json` 의 `ocr` 프롬프트를 8/13 exp_004 학습셋부터 반영했고,
exp_009 에서는 34,391행(학습의 40%)입니다. md5 까지 동일합니다.
Document Studio 호출의 89% 가 이 프롬프트라 **학습 조건과 운영 조건이 일치**합니다.
