## 0. 답변 요약

1. 현재 비중은 **생성 51.1% / public 46.2% / 사내 실문서 2.7%** 입니다.
2. 1,000건 넘는 생성 데이터는 **두 부류로 성격이 완전히 다릅니다.**
   - 서식 계열(std_hb·ctg_v2·ctg_quotation, 9,916행) — **패턴 다양성 확보됨.** 서식 12·18·4종, 표 열수 1~7 분포, 고유 어휘 6.8k~12.3k
   - 영수증 계열(synth_v1·v2·clean·receipt3000, 10,229행) — **패턴 단조.** 표는 전부 4열 고정, 고유 어휘 105~173종
3. **비중을 낮출 곳은 영수증 생성 10,965행이 맞습니다.** 서식 계열은 SS 도메인 직결인데 대체할 공개 데이터가 없어 지금 줄이면 견적서·계산서가 다시 무너집니다.
4. public을 높일 여지는 있지만 **여유분의 80%가 영수증**이라 총량만 늘고 SS 점수는 안 오릅니다(exp_009 vs exp_010 근거).
   예외가 **northwind 발주서 830건(Apache-2.0, 보유·미투입)** 으로, 유일하게 견적 계열 public입니다.
5. 골든셋은 현재 **평가 정답지 검증용 100건**이고 학습셋에 0행입니다. 학습 비중을 높이려면 별도 라벨링이 필요합니다.

- synth_clean·receipt3000은 **정답 길이 중앙값이 5자**인 크롭 조각입니다. 문서 단위 학습 신호가 아닙니다.
- 이미지 중복은 없습니다(고유 이미지 = 행 수). 다만 **synthetic 736행·human_annotated 720행은 각각 92장·90장을 8회 반복**한 것입니다(프롬프트는 8종으로 분산).
- 공통 약점 — **생성 데이터는 데이터셋당 지시문이 1종**입니다. 학습셋 전체 지시문은 45종인데 생성분에 다양성이 실리지 않았습니다.

**왜 많이 들어갔는가**: 다양성 때문이 아니라 **SS 도메인(무역·금융·행정 서식, 견적서)에 쓸 수 있는 공개 데이터가 없어서** 생성기로 채운 것입니다.
영수증 생성분은 그와 별개로, 초기 실험에서 크롭 물량을 늘리며 누적된 것입니다.
