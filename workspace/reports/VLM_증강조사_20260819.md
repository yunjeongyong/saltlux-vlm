# VLM 학습 데이터 증강 — 진행 현황과 다음 실험

담당 용윤정 · 2026-08-19 · 대상 LUXIA VLM 영수증 문서파싱

---

## 요약

증강 두 축을 만들었고, 그중 하나(온라인 이미지 증강)를 학습에 태워 측정했습니다.
결론은 **"아직 판정할 수 없다"** 이며, 이유는 모델이 아니라 **평가 체계**에 있습니다.
80건 표본에서 세 모델의 차이가 모두 95% 신뢰구간 0을 포함해 통계적으로 구분되지 않습니다.

측정 과정에서 **표 학습 데이터를 5,461건 늘렸더니 TEDS가 오히려 떨어졌다**는
반직관적 사실을 찾았고, 이것이 다음 실험의 근거가 됩니다.

---

## 1. 만든 것

### 축 A — 프롬프트·태스크 증강 (오프라인)

기존 GT에서 새 학습 샘플을 파생시킵니다. 이미지 추가도 사람 검수도 없습니다.

| 항목 | 값 |
|---|---|
| 원본 | exp004c 11,173행 |
| 증강 후 | **21,368행 (×1.91)** |
| 표 파생 | 8,959행 — 구조 QA / 마크다운 표 / JSON 배열 |
| 영수증 KIE | 1,236행 — 필드질의 / 금액질의 / JSON 추출 / 품목목록 |
| 프롬프트 다양화 | `page_ocr`·`receipt_markdown` 1종 → 8종 |
| 정합성 결함률 | **0.00%** (21,368행 중 1건) |

**상태: 생성 완료, 학습 미투입.** 현재 도는 exp_005는 축 B만 적용했습니다.

### 축 B — 온라인 이미지 증강

학습 중 이미지에만 변형을 겁니다. 전사 GT는 기하·광학 변환에 불변이라 정답이 안 바뀝니다.

변환 9종: 회전 ±8° / 원근 왜곡 / **말림** / **감열지 퇴색** / 그림자 / 블러 / 노이즈 / JPEG / 축소
굵은 둘은 영수증 특유의 축이며 일반 문서 OCR 레시피에 없습니다.

제외한 것: 좌우·상하 반전, 90·180° 회전, 색 반전 — GT를 읽을 수 없게 만듭니다.

**상태: exp_005로 학습 중 (98%).**

## 2. 검수에서 잡은 것

증강은 틀린 데이터를 대량 생산하는 가장 빠른 방법이기도 합니다. 실제로 5건을 걸렀습니다.

| 결함 | 내용 | 영향 |
|---|---|---|
| 주소를 상호명으로 | `"인천광역시 연수구 송도과학로 37"` | 오답 라벨 46건 |
| 일련번호를 날짜로 | `[영수증] 20160705-01-0003` → `0705-01-00` | 3건 |
| 스키마 불일치 | `json_kie` 프롬프트가 `items` 키를 요구하나 정답에 없음 | 161건 |
| 프롬프트 정렬 파괴 | 평가와 글자 단위로 같은 프롬프트를 다양화하려 함 | 892행 |
| 증강 코드 버그 | PIL `Image.QUAD` 꼭짓점 순서 오류 — 예외 없이 이미지만 찌그러짐 | 전량 |

마지막 둘이 특히 위험했습니다. **예외가 안 나서 학습은 정상으로 보이면서 성능만 떨어집니다.**
미리보기를 만들어 눈으로 본 것이 유일한 발견 경로였습니다.

**부수 발견**: 기존 합성 영수증 GT에 금액 계산 오류 2.2%(91장 중 2장).
"생성값이라 검수 불필요"라는 전제가 성립하지 않습니다.

## 3. 측정 결과

### 3-1. 세 모델 비교 (크롭 80건, 층화표본, 동일 입력)

| 모델 | 완전일치 | 숫자정확 | 금액정확 | 환각률 | CER ↓ | TEDS ↑ |
|---|---|---|---|---|---|---|
| exp_003 | 48.8% | 52.5% | 46.2% | 16.2% | 0.0630 | **0.7496** |
| exp_004 | 47.5% | **53.8%** | 45.0% | 12.5% | **0.0491** | 0.7290 |
| exp_005 (ckpt1500) | 48.8% | 52.5% | 45.0% | **11.2%** | 0.0824 | 0.7151 |

### 3-2. 그런데 이 차이는 판정할 수 없습니다

기준 exp_004 대비 승/패:

| 비교 | 지표 | 좋아짐 | 나빠짐 | 동일 | 95% 신뢰구간 | 판정 |
|---|---|---|---|---|---|---|
| exp_005 | CER | 1 | 4 | **35** | [-0.0817, +0.0078] | 구분 불가 |
| exp_005 | TEDS | 13 | 17 | 10 | [-0.0912, +0.0640] | 구분 불가 |
| exp_003 | CER | 2 | 4 | **34** | [-0.0483, +0.0104] | 구분 불가 |
| exp_003 | TEDS | 17 | 15 | 8 | [-0.0406, +0.0910] | 구분 불가 |

**CER 기준 40건 중 34~35건에서 세 모델이 완전히 같은 출력을 냅니다.**
"CER 0.0491 vs 0.0824"라는 차이는 실제로 갈리는 5~6건이 만든 것이고,
표본을 다시 뽑으면 뒤집힐 수 있습니다.

### 3-3. exp_005 학습 궤적

| 체크포인트 | CER ↓ | TEDS ↑ | AVG ↑ |
|---|---|---|---|
| ckpt-1250 | 0.1193 | 0.7135 | 0.7971 |
| ckpt-1500 | 0.0824 | **0.7151** | **0.8163** |
| ckpt-2000 | **0.0691** | 0.6826 | 0.8067 |

**두 지표가 반대로 움직입니다.** CER은 계속 개선 중(미수렴)인데 TEDS는 하락합니다.
이미지 증강이 텍스트 전사에는 도움이 되고 표 구조 인식은 방해한다는 해석이 가능합니다.

### 3-4. eval_loss는 성능 지표가 아닙니다

exp_005의 eval_loss는 0.1585로 exp_004의 0.1704보다 낮은데, CER·TEDS는 나빴습니다.
**앞으로 loss로 모델을 판단하면 안 됩니다.**

## 4. 기준선이 무효였습니다

exp_003의 기록값과 동일 크롭 재측정 결과가 다릅니다.

| | 기록값 | 재측정 |
|---|---|---|
| TEDS | 0.7286 | **0.7496** |
| CER | 0.1191 | **0.0630** |

크롭이 v2/v3로 재생성(회전·배율 보정)되면서 평가셋 자체가 달라졌습니다.
**"exp_003의 0.7286을 넘었나"라는 질문은 성립하지 않으며**, 재측정값이 새 기준선입니다.

## 5. 다음 실험 — 근거가 있는 순서

### 우선순위 1. 전량 1,019건 측정 (진행 중, 자동 예약)

지금 병목은 모델이 아니라 측정입니다. **80건으로는 무엇을 만들어도 개선을 증명할 수 없습니다.**
학습 종료 즉시 자동 시작되며 약 7시간 소요됩니다.

### 우선순위 2. exp_006 — 영수증 표 데이터 비중 복원

**근거**: 데이터 구성을 비교하면 반직관적 사실이 나옵니다.

| | exp_003 (TEDS 0.7496, 최고) | exp_004 (TEDS 0.7290) |
|---|---|---|
| 전체 | 4,496행 | 11,173행 |
| `html_table` | **0건** | 5,461건 (PubTabNet, 논문 표) |
| `receipt_markdown` | **1,496건** (GT의 95%에 `<table>`) | 182건 |

**표 학습 데이터를 5,461건 늘렸는데 TEDS가 떨어졌습니다.**
PubTabNet은 논문 표라 영수증과 도메인이 다릅니다. 반면 exp_003은 표 전용 데이터가 0인데도,
영수증 마크다운 1,496건의 GT 95%에 `<table>`이 들어 있어 **도메인이 맞는 표를 학습**했습니다.

**가설**: 표 성능은 양이 아니라 도메인 일치가 좌우한다.
**설계**: exp004c에서 `receipt_markdown`을 exp_003 수준으로 오버샘플(182 → 1,456행)하고,
`html_table` 비중을 낮춘다. 데이터 조합만 바꾸므로 구축 비용이 없다.

### 우선순위 3. exp_007 — 축 A(프롬프트·태스크 증강) 투입

TODO의 핵심 항목이며 **아직 미실행**입니다. 21,368행이 준비돼 있습니다.
단 이 증강분의 88%가 표 파생이라, 우선순위 2의 결과를 보고 조합을 정하는 편이 낫습니다.

### 우선순위 4. 증강을 텍스트 크롭에만 적용

궤적에서 CER은 개선, TEDS는 하락했습니다. 표 크롭에는 증강을 끄면 양쪽을 다 잡을 수 있습니다.
`img_augment.py`에 태스크 조건을 넣으면 됩니다.

### 보류 — 원본 영수증 추가 확보

CER 쪽 크롭 재료가 913개 중 892개(97.7%) 소진됐고 **원본 영수증 95장이 병목**입니다.
증강으로 올릴 수 있는 한계에 가깝습니다. 위 실험들로도 부족하면 신규 라벨링이 필요하며,
이는 증강이 아니라 데이터 구축이라 별도 리소스 요청이 필요합니다.

## 6. 미해결

| 항목 | 상태 |
|---|---|
| FSDP 전환 (학습 속도) | dtype 불일치(LoRA fp32 / 베이스 bf16) 원인 규명·수정 완료, **검증 대기** |
| 파생 태스크 평가셋 | 표·KIE 능력을 잴 val/test가 없음 |
| `high.json` 채택 여부 | A/B 비교 스크립트 준비 완료, 미실행 |
| val = test 문제 | 두 파일 md5 동일. `--load-best`가 val로 고른 체크포인트를 test로 재는 구조 |
| 평가셋 GT 오류 | 90장 중 28장에서 의심 신호(한자 혼입·GT 누락 등) |
