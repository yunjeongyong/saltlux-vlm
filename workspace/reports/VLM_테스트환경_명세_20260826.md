## 0. 왜 필요한가

같은 평가셋(SS 400건)에서 나온 수치인데 **비교 조건이 서로 달라** 해석이 엇갈렸습니다.

- `DocStudio alt/high` 0.9032 vs 저희 `exp_004` 0.8956 → **모델 차이로 오인**
- 실제로는 **동일한 exp_004 어댑터**이고, 차이는 **전처리(레이아웃 검출) 유무**

아래는 두 경로의 실제 구성과 통일 방안입니다.

## 3. 공통 구간 (이미 통일됨)

파싱 이후 단계는 강한빛 선임님 파이프라인을 그대로 사용해 동일합니다.

| 단계 | 설정 |
|---|---|
| KIE 추출 | `kie_from_parsing.py` → `http://124.198.30.179:15006/v1` |
| KIE 모델 | 서버가 모델명을 무시하고 **`public/gemma-4-31B-it`** 로 응답 (검증) |
| 채점 | `eval_kie.py` — 숫자 허용오차 `1e-4`, 문자 정규화 편집거리 유사도, 표 행 순서무관 그리디 매칭 |
| 정답 | `kie_dataset/` 400건 (GPT-5.6 생성 후 검수) |

**주의** — 실행 리포트의 `model` 필드는 서버 응답이 아니라 `--api-model` 입력값을 그대로 기록합니다. 기존 리포트에 `luxia3.5-120b-sft-v1.4` 로 남아 있으나 실제 추론은 gemma 입니다.

## 4. 통일 방안 (제안)

### 안 A — 제품 파이프라인에서 비교 (권장)

GPU 7번 엔진에 **exp_009를 병합해 서빙**하고, 동일 API로 400건을 재측정합니다.

- 장점: 실제 배포 형태와 동일. 전처리·엔진·디코딩이 모두 같아 **모델 차이만 남음**
- 필요: `merged_model.py` 로 exp_009 병합 (약 30분) + 컨테이너 재기동
- 근거: exp_009 단독(0.8981)이 exp_004+전처리(0.9032)에 0.5%까지 접근 → 전처리를 붙이면 넘을 가능성

### 안 B — 어댑터 단독으로 비교

저희 측정 방식대로 전처리 없이 모든 모델을 재는 방식. 이미 exp_004 / exp_009 는 완료.
- 장점: GPU 7번을 안 건드림
- 단점: 제품 성능이 아니라 **VLM 단독 성능**만 봄

**두 지표를 병기하는 것이 가장 정확합니다.** 안 A는 제품 관점, 안 B는 모델 관점입니다.
