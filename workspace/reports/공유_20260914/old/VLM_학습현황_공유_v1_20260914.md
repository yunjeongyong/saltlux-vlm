구성: 슬라이드 9장 (표지 + 8장).

> **이미지 사용 원칙** — PPT에는 `assets/` 의 **낱개 이미지**(원본 문서 / 정답 시각화 / 모델 출력 시각화 / 대조표가 각각 별도 파일)를 쓴다. 어느 슬라이드에 어떤 파일을 몇 장, 어떻게 놓을지는 **`이미지_배치_가이드.md`** 에 전부 적혀 있다. `images/` 의 합성 패널(`d*/r*/p*/g*`)은 배치 참고용 예시일 뿐이다.

그림은 두 종류 — `images/0N_*.png` 통계 차트, `images/{d,r,p}N_*.png` 실제 문서 이미지·정답·모델 출력 패널(16:9, 슬라이드 한 장 꽉 채워 배치). 각 `## 슬라이드 N` 이 PPT 한 장에 대응하며, `images/` 의 그림을 해당 슬라이드에 배치한다.

## 슬라이드 6 — 문제점 ①: 학습셋 오염 (공개 데이터 FATURA2 4,000행)

exp_012·013 성능 급락의 원인 · 규명 및 수정 완료 (2026-09-07)

![FATURA2 — 이미지에는 표가 있는데 정답에는 없다 (학습 정답 vs 복원 정답)](images/p1_fatura2_label.png)

![같은 견적서, 오염 전후 모델 출력 — exp_009 vs exp_013](images/p2_table_omission.png)

![FATURA2 영향과 복원](images/05_fatura2_fix.png)

### 원인
- `doc_parsing/invoice` 4,491행 중 **4,000행이 "표는 HTML `<table>`로 출력" 지시를 받고도 정답에 표가 없음**
- FATURA2는 **필드추출(KIE)용 데이터셋** — 품목 표를 영역만 표시하고 내용 미기재. 데이터셋 입장에서는 결함이 아니라 설계
- **용도가 다른 데이터를 다른 용도로 쓴 것**
- 한 파일(`pub_invoice/train.jsonl`)에 두 공개셋(invoices-donut 491 · FATURA2 4,000)이 같은 task명으로 섞여 학습셋 단계에서 안 보였음

### 영향
- 모델이 "표를 요구받아도 표 없이 답한다"를 4,000회 학습
- 견적서 표 출력 100/100 → 47/100, 인보이스 100/100 → 37/100
- SS 400건 85.6% → 74.7% (−10.9%p)
- 표를 뱉은 272건은 85.5%로 정상 — **실력은 멀쩡, 표 누락 습관이 128건을 끌어내림**

### 조치
- **빼지 않고 복원**: exp_009(표 100/100 모델)로 표를 읽어 채우고, 원본 SUB_TOTAL과 금액 합계로 검산
  - 검산 통과 2,734 (68.4%) · 검산 불가 600 (15.0%) → 유지 / 검산 실패 666 (16.7%) → 제외
- `exp015_clean` 40,010행 · 오염 4,139 → 139행 (139는 실제 표 없는 정상 케이스) · 검증 13항목 통과
- registry에 `revoked` 전이 → 재유입 시 `validate_taxonomy.py`에서 자동 FAIL
- 재학습 완료 (9/10) · **9/14 SS 400건 파싱 결과: 견적서 표 100/100 · 인보이스 표 100/100 · 영수증 92/100 · 명세서 100/100 — exp_009와 동일 수준으로 회복** (KIE 정확도 채점은 추출기 복구 후)
- 사내 합성 데이터(std_hb 5,000 · CTG 3,916)는 **전부 정상**

### 재발 방지 (등록 절차 추가 제안)
- 공개 데이터 도입 시 **"원본 데이터셋의 과제 ↔ 우리 용도" 일치 확인** (라이선스만 보고 통과시키면 반복)
- "지시문이 표를 요구하는데 정답에 `<tr>`이 없는 행" **자동 검사** — 이번 4,000행은 등록 단계에서 걸렸어야 함

## 슬라이드 7 — 문제점 ②: 학습 데이터 구조 (오염과 별개로 남은 것)

4개 카드 구성.

### 1. 도메인 불균형 — 평가와 학습이 안 맞음
- 견적서: SS 평가 25% ↔ 학습 2.4% (1,000행)
- 학술 표·공공행정: 평가 0% ↔ 학습 24.4%
- 명세서·계산서 실패 필드는 전부 "칸 안에 여러 줄로 접힌 긴 텍스트 블록" (shipper_address 86건 · purpose 97건 · shipment_route 94건 등)
- 견적 계열 public은 northwind 830건(Apache-2.0)이 유일 — 보유·미투입

### 2. 프롬프트 편중 — 72%가 지시문 1종
- `doc_parsing` 19개 유형 12,741행이 지시문 하나를 공유, 그 문장이 **SS 평가 프롬프트와 글자까지 동일**
- 전체 21개 task · 28,627행(72%)이 프롬프트 1종
- 생성 데이터는 데이터셋당 지시문 1종 (45종 보유 중 미적용)
- "이미지 그대로 출력" 원칙 위반은 지시문 45종 전수 점검 결과 **0건** → 문제는 지시문이 아니라 라벨 쪽

### 3. 라이선스 — 상용 납품 차단 요소
- **PubTabNet 5,461행 (CC BY-NC-SA)** 이 exp_015·016 계보에 잔존 → 상용 모델에 쓰려면 제거 필요 (exp_014는 제외판)
  - 대체: FinTabNet_OTSL (CDLA-Permissive) 3,000행
- AI-Hub 2종·KorIE 2종 라이선스 unknown → GitLab 커밋 보류. AI-Hub는 제3자 제공 제한 — **재배포 해당 여부 판단 요청**
- `guard_license.py` 통과를 릴리즈 조건으로 설정

### 4. 사내 실문서 부족 · 영수증 생성 포화
- 사내 실문서 학습 자산 고유 **455장** (전체의 2.7%)

### 관찰된 실패 유형
- **원본 오타를 모델이 교정해버림** — `P브로커리`(원본·정답) → `P 브로콜리`로 답변. "이미지 그대로 출력" 원칙 위반, 프롬프트 개선안 7번이 겨냥

- **명세서·계산서**: 여러 줄 접힌 긴 텍스트 블록 필드에 실패 집중

### 평가 인프라에서 발견·수정한 것
- 평가 스크립트 bash 인자 버그(`E="exp011}"`) → 세 실험 스킵 후 "완료" 출력. exp_011·012·013 점수가 비어 있던 원인. 수정 완료

### SS 평가 방법 관련 미결
