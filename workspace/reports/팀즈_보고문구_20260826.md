## A. 파트장님 질문 답변 — "alt/high 랑 exp_004 같은 모델인데 왜 결과가 다르냐"

> 김동영 파트장님,
>
> alt/high 와 exp_004 동일성 확인했습니다. **가중치는 동일한 게 맞습니다.**
>
> GPU7 컨테이너가 서빙 중인 `merged_model` 에서 base 를 뺀 값과, exp_004 LoRA 어댑터로 계산한 ΔW 를 직접 대조했습니다.
>
> ```
> layer 11   ‖GPU7−base‖ 1.4330   exp_004 ΔW 1.4300   잔차 7.4%
> layer 15   ‖GPU7−base‖ 1.1822   exp_004 ΔW 1.1790   잔차 8.4%
> layer 19   ‖GPU7−base‖ 1.3097   exp_004 ΔW 1.3070   잔차 7.4%
> layer 23   ‖GPU7−base‖ 1.3515   exp_004 ΔW 1.3472   잔차 8.7%
>
> [대조군] exp_009 110% / exp_007 140% / exp_006 147% / exp_005 152%
> ```
>
> 잔차 7~9%는 bf16 저장 오차 범위이고, 다른 어댑터를 넣으면 전혀 맞지 않습니다. **alt/high = exp_004 확정입니다.**
>
> **그런데 점수가 다른 이유는 가중치가 아니라 시스템입니다.** 세 층에서 차이가 나고, 각각 실제로 재봤습니다.
>
> **1) 서빙 엔진** — 같은 가중치·같은 프롬프트·같은 greedy 로 receipt 100건을 GPU7 엔진(vLLM)과 제 로컬(transformers)에서 각각 뽑아 대조했습니다.
>
> ```
> 평균 CER              0.1072
> 사실상 동일(CER<0.02)   53 / 100
> 크게 갈림(CER>0.20)     15 / 100
> ```
>
> 엔진 자체는 결정적입니다(같은 입력 3회 → md5 동일). 그런데도 갈리는 건 MoE 구조 때문입니다. 토큰마다 전문가 256개 중 8개를 고르는데, 커널 구현 차이로 생긴 미세한 수치 차가 전문가 선택을 한 번 뒤집으면 그 뒤 출력이 통째로 갈라집니다. 실제로 receipt41은 엔진에서만 반복 루프가 났습니다.
>
> **2) 파이프라인** — Document Studio 는 PP-DocLayoutV3 로 영역을 나눠 영역별 전용 프롬프트로 VLM 을 문서당 N회 호출하고 좌표 순으로 재조립합니다. 저희는 페이지 한 장을 통째로 1회 호출합니다. 같은 exp_004 가중치로 뽑은 두 출력의 일치도가 **본문 CER 0.42 / 표 TEDS 0.49** 로, 절반 이상이 다른 텍스트입니다.
>
> **3) 디코딩** — DocStudio 워커는 temperature 를 지정하지 않아 vLLM 기본값(샘플링)으로 돌고, 저희 측정은 greedy 입니다.
>
> 정리하면 **alt/high 행은 "exp_004 가중치를 쓴 Document Studio 제품 전체"** 점수이고, **exp_004 행은 "그 가중치만 떼어 VLM 단독으로 돌린"** 점수입니다. 0.0076 차이는 모델 차이가 아니라 전처리·조립·디코딩이 만든 차이입니다.
>
> 공정한 비교를 위해 **exp_004 400건을 GPU7 엔진으로 재측정 완료**했고, exp_009 도 병합 모델을 만들어 뒀습니다. 컨테이너만 올라가면 400건이 10분이면 끝납니다.
