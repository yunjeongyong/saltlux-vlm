## 한 줄 요약

**지시문 45종은 원칙("이미지 그대로 텍스트 출력")을 하나도 어기지 않는다. 문제는 다른 데 있다 — `doc_parsing` 19개 유형 12,741행이 지시문 단 하나를 공유하고, 그 문장이 SS 평가 프롬프트와 글자까지 똑같으며, 생략을 막는 안전장치가 없다.**

이번 FATURA2 오염 4,000행이 하필 그 프롬프트에 실렸다. 프롬프트가 하나뿐이라 오염이 분산되지 않고 그대로 축적됐다.

## 1. 원칙 점검 — 위반 0건

김동영 파트장 2026-09-02 지시: *"학습 데이터는 SS 평가 데이터와 별개로 이미지 그대로 텍스트 출력하도록 고정해 주세요"*

| 분류 | 행 | 비중 | 지시문 |
|---|---|---|---|
| **전사** — 그대로 옮긴다 | 19,305 | 48.3% | 14종 |
| **구조화** — 전사하되 표는 HTML | 20,237 | 50.6% | 30종 |
| **변형** — 요약·해석 | **0** | **0.0%** | **0종** |
| 미분류 | 468 | 1.2% | 1종 |

**45종 전부 부합한다.** 미분류 1종은 *"다음 문서 페이지의 전체 본문 텍스트를 추출하라"*로, 읽어보면 전사가 맞다.

오히려 **18종 / 9,251행(23.1%)은 안전장치를 명시**하고 있다:

> *"이미지에 없는 내용을 추측해서 넣지 마라"*
> *"원문의 한국어/영어 텍스트를 의역하지 말고 그대로 보존하라"*
> *"텍스트를 수정, 번역, 요약, 정규화하거나 주변 문맥으로 추론하지 않는다"*
> *"페이지에 있는 내용을 생략 없이 전부 출력하라"*

**결론: 이번 사고는 지시문이 원칙을 어겨서가 아니라 라벨이 이미지 내용을 누락해서 생겼다.** 점검의 초점은 지시문이 아니라 라벨 쪽에 두어야 한다.

> **분류기 오탐 기록** — 초안 분류기가 2,390행을 위반으로 잘못 잡았다. `분석해서`라는 동사에 걸렸는데 실제 지시는 "분석해서 **그대로 옮겨라**"였고, `의역`·`요약`은 전부 **부정문**("의역하지 말고", "요약하지 않는다")이었다. 지시문 전문과 라벨을 대조해 오탐임을 확인하고 고쳤다. **판정은 동사가 아니라 "무엇을 내놓으라 하는가"로 해야 한다.**

## 2. 진짜 문제 — 프롬프트 편중

김동영 파트장 2026-09-02 지시: *"데이터 유형 별로 프롬프트는 한번 더 다양하게 구성해서 학습해 보면 좋을 것 같습니다"*

### 2-1. 19개 유형이 지시문 하나를 공유한다

`doc_parsing` 계열 19개 task **12,741행 전부**가 이 한 문장을 쓴다.

```
이 문서의 내용을 마크다운으로 정리해줘. 표는 HTML <table> 로 출력해라.
```

선하증권, 원산지증명서, 위임장, 보험증권, 세금계산서, 포장명세서… 문서 성격이 전혀 다른데 지시가 같다.

### 2-2. 그 문장이 SS 평가 프롬프트와 똑같다

`scripts/parse_ss_docs.py` · `parse_ss_via_engine.py` 의 평가 프롬프트:

```python
"bill":      "이 문서의 내용을 마크다운으로 정리해줘. 표는 HTML <table> 로 출력해라.",
"invoice":   "이 문서의 내용을 마크다운으로 정리해줘. 표는 HTML <table> 로 출력해라.",
"quotation": "이 문서의 내용을 마크다운으로 정리해줘. 표는 HTML <table> 로 출력해라.",
```

**글자까지 동일하다.** 학습 12,741행이 이 한 지점에 몰려 있고, 평가도 같은 지점만 두드린다. 그 지점이 오염되면 방어할 여지가 없다 — 이번에 실제로 그렇게 됐다.

### 2-3. 안전장치가 없다

이 지시문에는 *"생략 없이"* · *"지어내지 마라"* 가 **없다**. 표를 요구하기만 하고, 빠뜨리지 말라는 말이 없다.

|---|---|---|---|
| `doc_parsing/*` 19종 | 12,741 | 1종 | **없음** |
| `receipt_crop_text` | 11,990 | 1종 | 없음 (다만 본문에 상세 규칙 포함) |
| `page_ocr` | 2,000 | 1종 | **없음** |
| `receipt_crop_table` | 1,896 | 1종 | 있음 |
| `html_table` | 5,461 | **12종** | 일부 |
| `receipt_markdown` | 3,284 | **8종** | 일부 |
| `parsing/전체텍스트` | 2,499 | **5종** | 일부 |
| `doc_parsing/government`·`paper` | 139 | **8종** | 있음 |

**21개 task · 28,627행(72%)이 프롬프트 1종이다.**

## 3. 개선안

### 3-1. `receipt_markdown` 방식을 그대로 넓힌다

이미 잘 되고 있는 본보기가 있다. `receipt_markdown`은 **같은 이미지·같은 정답에 지시문만 8종**을 붙여 학습한다(프롬프트 증강 1,274행).

```
이 영수증의 내용을 마크다운으로 정리해줘.
이 영수증에 인쇄된 글자를 위에서부터 순서대로 그대로 옮겨 적어라.
영수증 사진을 보고 인쇄된 문구를 그대로 재현하라. 임의로 고쳐 쓰지 마라.
영수증 이미지를 읽고 보이는 내용을 있는 그대로 텍스트로 출력하라.
이 영수증 이미지의 전체 내용을 텍스트로 추출하라. 설명 없이 결과만 출력하라.
영수증에 적힌 항목과 금액을 보이는 순서대로 빠짐없이 옮겨 적어라.
이 영수증에 보이는 모든 글자를 읽기 순서대로 한 번씩만 전사하라.
이 영수증을 필사하듯 그대로 텍스트로 변환해줘. 없는 내용을 추가하지 마라.
```

**이 방식을 `doc_parsing` 계열에 적용한다.** 데이터를 새로 모을 필요가 없다 — 있는 행에 지시문만 바꿔 붙이면 된다.

### 3-2. `doc_parsing` 공통 프롬프트 제안 8종

기존 1종을 유지하되(평가와의 연속성) 7종을 더한다. **셋은 안전장치를 명시**한다 — 이번 사고의 재발을 프롬프트 쪽에서도 막는다.

| # | 문안 | 의도 |
|---|---|---|
| 1 | 이 문서의 내용을 마크다운으로 정리해줘. 표는 HTML `<table>` 로 출력해라. | 기존 유지 (평가와 동일) |
| 2 | 이 문서에 적힌 내용을 **생략 없이 전부** 옮겨 적어라. 표는 HTML `<table>` 로 출력한다. | **누락 방지** ← 이번 사고 대응 |
| 3 | 문서 이미지를 그대로 텍스트로 옮겨라. 품목이나 항목이 표로 되어 있으면 HTML `<table>` 로 복원한다. | 표 누락 방지 |
| 4 | 이 문서를 필사하듯 마크다운으로 변환해줘. **이미지에 없는 내용을 지어내지 마라.** 표는 HTML `<table>` 로 쓴다. | **환각 방지** |
| 5 | 문서에 보이는 글자를 읽기 순서대로 한 번씩만 전사하라. 표 영역은 HTML `<table>` 로 낸다. | 중복 출력 방지 |
| 6 | 이 문서의 머리말·본문·표를 순서대로 모두 마크다운으로 출력하라. 설명이나 인사말 없이 결과만 낸다. | 구조 완전성 |
| 7 | 문서 이미지를 원본 구조 그대로 마크다운으로 복원해라. **원문 표기를 고쳐 쓰지 말고 보이는 대로 적는다.** 표는 HTML `<table>`. | **과잉 교정 방지** ← 아래 3-4 참조 |
| 8 | 이 문서에서 읽을 수 있는 모든 내용을 마크다운으로 옮겨라. 표는 HTML `<table>` 로, 나머지는 평문으로 쓴다. | 형식 분리 |

### 3-3. `page_ocr` · `receipt_crop_text` 보강

`page_ocr` 2,000행이 *"이 문서에 적힌 텍스트를 순서대로 옮겨 적어줘"* 한 문장뿐이다. `parsing/전체텍스트`가 이미 쓰는 5종을 공유하면 즉시 해결된다.

`receipt_crop_text` 11,990행은 본문에 상세 규칙이 들어 있어 품질은 괜찮지만, 짧은 변형 2~3종을 더하면 프롬프트 의존을 줄일 수 있다.

### 3-4. 과잉 교정을 프롬프트로 막는다

SS 평가에서 확인된 실패 하나가 프롬프트로 대응 가능하다.

> 영수증에 **`P브로커리`**라고 인쇄돼 있고 정답도 그대로인데, 모델이 **`P 브로콜리`**로 "고쳐" 답했다.

모델이 상식으로 교정해버린 것이다. 위 3-2의 7번 문안(*"원문 표기를 고쳐 쓰지 말고 보이는 대로 적는다"*)이 이 실패를 정면으로 겨냥한다. 현재 `doc_parsing` 계열에는 이런 문구가 전혀 없다.
