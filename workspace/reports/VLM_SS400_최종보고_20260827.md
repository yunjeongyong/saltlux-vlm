## 3. alt/high = Document Studio + exp_004 — 검증

파트장님 질문("같은 모델인데 왜 결과가 다르냐")에 대한 근거입니다.

대조군 잔차 — exp_009 110% / exp_007 140% / exp_006 147% / exp_005 152%.
잔차 7~9% 는 bf16 저장 오차 범위입니다. **동일 가중치가 맞습니다.**

### 종단 검증

GPU7 엔진 로그(107MB)에서 Document Studio `prompts/high.json` 프롬프트를 찾았습니다.

| 프롬프트 | high.json | fast.json |
|---|---|---|
| `ocr` | **4,746회** | 0회 |
| `table` | **511회** | 0회 |
| `image`/`chart` 류 | 60회 | 0회 |

**alt/high = Document Studio high 파이프라인 + GPU7 엔진(exp_004 병합)** 이 확정됩니다.

### 점수가 다른 이유

alt/high 는 **제품 전체**의 점수이고, exp_004 행은 **그 가중치만 떼어 VLM 단독**으로 돌린 점수입니다.
차이를 만드는 것은 가중치가 아니라 파이프라인입니다.

| | Document Studio | 우리 측정 |
|---|---|---|
| 레이아웃 검출 | PP-DocLayoutV3 로 영역 분할 | 없음 |
| VLM 호출 | 영역마다 1회 (문서당 N회) | 페이지당 1회 |
| 프롬프트 | 영역 종류별 전용 | 문서 종류별 1종 |
| 조립 | 좌표 순 재조립 | 모델 출력 그대로 |
| 디코딩 | vLLM 기본(샘플링) | greedy |

같은 exp_004 가중치로 뽑은 두 출력의 일치도는 **본문 CER 0.42 / 표 TEDS 0.49** 로, 절반 이상이 다른 텍스트입니다.

## 5. 내부 지표 — CER / TEDS (자체 평가셋 1,019 크롭)

SS 셋에는 사람이 만든 파싱 정답이 없습니다. **진짜 정확도는 이쪽이 유일한 근거**입니다.
유계 CER(0~1) 로 전 실험을 통일했습니다.

| 모델 | CER↓ | TEDS↑ | 완전일치↑ | 반복루프 | 표 파싱실패 |
|---|---|---|---|---|---|
| 학습 전 base | 0.1378 | 0.6647 | 57.9% | 0 | 10 |
| exp_003 | 0.1302 | 0.7287 | 57.2% | 1 | 1 |
| **exp_004 (현 배포)** | **0.1063** | 0.7079 | **64.2%** | 7 | 6 |
| exp_005 | 0.1081 | 0.6831 | 65.3% | 1 | 9 |
| exp_006 | 0.1177 | 0.6916 | 64.4% | 0 | 3 |
| exp_007 | 0.1155 | 0.6691 | 63.1% | 0 | 5 |
| exp_008 | 0.1305 | 0.6879 | 60.8% | 0 | 5 |
| **exp_009 (최종 24,646 step)** | 0.1155 | **0.7476** | 63.5% | **0** | 3 |
| **1차 목표** | **≤ 0.097** | **≥ 0.739** | **≥ 67%** | | |

- **TEDS 목표 달성** (0.7476 ≥ 0.739).
- CER 0.1155 는 목표 미달이고 exp_004(0.1063)보다 높습니다.
- **반복루프 7건 → 0건.** 운영에서 가장 위험한 실패 유형이 사라졌습니다.
- 표 파싱 실패 base 10건 → 3건.

**해석** — exp_009 는 표와 안정성을 얻고 텍스트 CER 을 조금 내준 모델입니다.
SS 400건 KIE 에서 exp_009 가 1위인 것은 그 교환이 실제 문서에서는 이득이었다는 뜻입니다.

### SS 셋의 CER/TEDS 는 순위 근거로 쓸 수 없습니다

기준선으로 쓸 수 있는 `data/<type>/jsons` 가 Document Studio 자신의 1차 라벨링입니다.
Document Studio base 와 대조하면 평균 CER 0.1007 / 완전일치 56·398 / CER<0.05 가 207·398 로,
**절반 이상이 거의 같은 문서**입니다. base 가 자기 자신을 채점하는 셈이라 편향됩니다.

| 지표 | 유효한 근거 |
|---|---|
| CER / TEDS | 1,019 크롭 셋 (사람 정답 있음) |
| KIE 정확도 | SS 400건 (GPT-5.6 검증 정답 `kie_dataset`) |
| SS 의 CER/TEDS | ❌ 파싱 정답 없음 — 참고용 "DS 와의 거리" |

**`receipt36` (평균 0.473)** — 구겨지고 기울어진 영수증.

**Document Studio base 만 12행을 다 잡아 0.902** 입니다. 상호명도 넷 다 틀립니다.

**`quotation-80` (평균 0.483)** — 네 구성 모두 최저. 견적서 구조 자체가 어렵습니다.

레이아웃 검출을 붙여야 할 근거이기도 합니다.
