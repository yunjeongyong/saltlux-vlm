8장 전부를 `device_map=auto` **파이프라인 병렬**로 씁니다. FSDP는 exp_005·exp_006에서 두 번
시도했으나 LoRA(fp32)와 베이스(bf16)의 dtype 불일치로 실패했습니다. 모델 생성 직후 bf16으로
정렬해도 Trainer의 bf16 혼합정밀도가 fp32 마스터 사본을 만들면서 학습 스텝에서 다시
어긋납니다. 미해결 과제로 남아 있습니다.

**모든 학습 모델이 베이스를 넘습니다.** 강조점이 갈립니다 — 텍스트는 exp_004(CER −22.9%),
표 구조는 exp_009(TEDS +12.3%)가 최고이고, 한 모델이 두 지표를 동시에 잡은 적은 없습니다.

**exp_009 TEDS 0.7464 는 내부 1차 목표(0.739)를 처음 넘긴 수치**입니다. 표 파싱 자체를
실패하던 케이스(TEDS<0.3)도 exp_004 의 7건에서 2건으로 줄었습니다.

### 실효 사용성

파싱 정확도만으로는 실사용 만족도가 과소평가됩니다. exp_004 기준 텍스트 921건을 분해하면:

| 구분 | 건수 | 비율 |
|---|---:|---:|
| 완전일치 | 591 | 64.2% |
| 틀렸으나 숫자는 전부 정확 | 232 | 25.2% |
| 숫자가 틀림 (크리티컬) | 98 | 10.6% |

틀린 330건 중 **232건(70.3%)은 숫자가 정확하고 글자만 틀립니다.** RAG 로 LLM 에 넣으면
실사용에 지장이 없는 유형이라, **실효 사용성은 89.4%** 로 볼 수 있습니다.

   100건 / SS 이미지 100건이 이 서버에 없습니다(`yyj` · `dykim` · `hbkang` 전부 확인).
