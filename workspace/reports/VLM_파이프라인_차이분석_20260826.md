# DocStudio vs 자체 측정 — 파이프라인 차이 분석

2026-08-26 · 용윤정 · 회의 보고용

`DocStudio alt/high 0.9032` 와 `저희 exp_004 0.8956` 의 차이가 **모델 차이인지 조건 차이인지**
확인한 결과입니다. 결론부터 — **같은 어댑터이고, 차이는 파이프라인 구조입니다.**

## 2. DocStudio 파싱 파이프라인 구조

`documentai_api/src/models/paddle_ocr_vl.py`

```python
PaddleOCRVL(
    vl_rec_backend      = "vllm-server",
    vl_rec_server_url   = URL,
    layout_detection_model_name = "PP-DocLayoutV3",
    layout_detection_model_dir  = "/model/PP-DocLayoutV3",
)
```

| 단계 | 처리 |
|---|---|
| ① 레이아웃 검출 | **PP-DocLayoutV3** (PaddleX, 126MB) — 영역 종류·좌표 검출 |
| ② 영역별 크롭 | PaddleOCR 파이프라인이 분할 |
| ③ 영역별 VLM 호출 | 종류별 전용 프롬프트로 **문서당 N회** 호출 |
| ④ 조립 | 좌표 기준 마크다운 재구성 |

**`fast` / `high` 의 정체 = 프롬프트 세트 차이입니다.** 모델은 같습니다.
`luxia-document-layout-detection-V3/prompts/{fast,high}.json`

| 태스크 | fast | high |
|---|---|---|
| ocr | `"OCR:"` | 20줄 상세 지시문 (LaTeX 규칙·반복 금지·환각 금지) |
| table | `"Table Recognition:"` | Role 지정 + 시각적 격자 우선 규칙 |
| 그 외 | `Formula/Image/Chart/Seal Recognition:` | 각각 상세판 |

`high` 의 ocr 프롬프트에는 **반복 생성을 억제하는 지시**가 명시돼 있습니다.
> *"각각의 보이는 줄은 최대 한 번만 출력한다"*, *"마지막으로 보이는 내용을 전사한 즉시 출력을 종료한다"*

## 3. 저희 측정 방식

| 단계 | 처리 |
|---|---|
| 전처리 | **없음** |
| VLM 호출 | **페이지 이미지 1장 통째로, 문서당 1회** |
| 프롬프트 | `"이 영수증의 내용을 마크다운으로 정리해줘."` (학습 시와 동일) |
| 조립 | 모델 출력 그대로 |

## 4. 차이 정리

| 층 | DocStudio | 저희 | 영향 | 확인 근거 |
|---|---|---|---|---|
| **전처리** | PP-DocLayoutV3 영역 검출 → 종류별 처리 | 없음 (페이지 통째) | **큼** | 코드 |
| **프롬프트** | 영역 종류별 전용 (`high.json`) | 단일 프롬프트 | **큼** | 파일 |
| **VLM 호출 횟수** | 문서당 N회 (영역 수) | 문서당 1회 | **큼** | 코드 |
| **디코딩** | **샘플링** (기본값 사용) | greedy | 측정 중 | **엔진 로그** |
| ~~사고모드~~ | **`enable_thinking: False`** | 동일하게 끔 | **없음** | **엔진 로그** |
| 가중치 | 병합 후 bf16 저장 | 베이스 + 어댑터 분리 로드 | 작음 | 확인 |
| 엔진 | vLLM 컨테이너 3.1.7 | transformers `generate` | 작음 | 설정 |
| 서버 | 운영 242 / 테스트 52 GPU7 | 52 GPU 4~6 | 없음 | 파트장님 자료 |

**엔진 로그(`VLM/engine/logs/debug.log*`)로 확인한 사실**

- `enable_thinking': False` 가 **154회** 기록 — 사고모드는 **저희와 동일하게 끕니다.**
  (엔진을 직접 호출하면 사고 과정이 나오지만, 실제 파이프라인은 이 값을 넘깁니다)
- `temperature` · `top_p` · `top_k` · `max_tokens` · `repetition_penalty` 가 **로그에 한 번도 없음**
  → `model_config.py` 의 `params` 가 비어 있는 것과 일치. vLLM 이 모델 `generation_config.json`
  기본값(`do_sample:true, temperature:1.0, top_k:20, top_p:0.95`)을 사용합니다. **샘플링입니다.**

## 5. 실제 출력 비교 — 차이가 드러나는 지점

동일 문서 `receipt00`

**DocStudio high**
```
# 쭈꾸미낙지볶음전문점 대성        ← 상호명을 제목으로 인식
사업자번호 : 5023094239
# 영수증                            ← 섹션 구분
<table frame="hsides" rules="groups" width="100%">
```

**저희 exp_009**
```
사업자번호 : 5023094239           ← 상호명 누락
<table><tr><td>영수증 #</td>...    ← 메타데이터도 표 안에 포함
```

**상호명이 빠졌습니다.** 전처리가 `title` 영역을 따로 잡아주는 것과, 페이지를 통째로 넣고
모델이 판단하는 것의 차이입니다.

KIE 정확도의 `general`(상호명·주소·날짜 등)에서 저희가 낮은 이유가 여기 있습니다.
exp_009 `general` 0.8966 vs DocStudio high 0.9007

## 6. 결론

**`0.9032 vs 0.8981` (0.5%) 는 모델 성능 차이가 아니라 파이프라인 구조 차이입니다.**

- DocStudio high = **exp_004 + 레이아웃 검출 + 영역별 전용 프롬프트**
- 저희 exp_009 = **exp_009 단독, 전처리 없음, 단일 프롬프트**

**동일 조건에서 비교하면 exp_009 가 exp_004 보다 낫습니다** (0.8981 vs 0.8956, 둘 다 전처리 없음).

## 7. 제안 — 동일 조건 비교 방법

`PaddleOCRVL` 은 오픈소스이고 레포에 `PaddleOCR` · `PaddleX` 가 포함돼 있습니다.
**`vl_rec_server_url` 만 exp_009 서빙으로 바꾸면** 전처리·프롬프트·조립이 전부 동일해지고
**VLM 만 exp_004 ↔ exp_009 로 갈립니다.**

```python
PaddleOCRVL(
    vl_rec_backend    = "vllm-server",
    vl_rec_server_url = "<exp_009 vLLM 서빙 주소>",   # 여기만 교체
    layout_detection_model_name = "PP-DocLayoutV3",
)
```

| 필요 작업 | 소요 |
|---|---|
| exp_009 병합 (`merged_model.py`) | 약 30분 |
| vLLM 설치 + 서빙 | 약 1시간 |
| PaddleOCRVL 로 400건 재파싱 | 수 시간 |

**파트장님 운영 엔진을 건드리지 않고** 저희 쪽에서 독립적으로 동일 조건 비교를 만들 수 있습니다.

## 8. 회의 때 확인 부탁드릴 사항

1. worker 가 디코딩 파라미터를 정말 넘기지 않는지 (`model_config.py` `params` 비어 있음)
2. 디코딩을 기본값(샘플링)으로 두신 것이 의도인지 — 샘플링이면 같은 문서를 두 번 돌려도 결과가 달라져 재현성이 없습니다
3. 운영(242) 과 테스트(52 GPU7) 엔진의 관계 — 동일 이미지·동일 모델인지
4. 서빙 모델 이력 기록 — `merge_model/` 에 어댑터명·베이스·일시·md5 를 남기는 규칙
