## 개요

exp_012 학습셋 **43,500장(47,686행)** 을 전수 검사했다.
한 쪽에 10건씩 배치한 검토 자료 **4,359쪽**을 만들어 이미지와 정답을 눈으로 대조하고,
정량 판정이 가능한 항목은 자동 검사를 병행했다.

결과로 **2,129행(4.46%)** 에서 이상을 확인했고, **정제본을 별도로 만들어 재검사까지 마쳤다.**
원본 이미지와 라벨은 수정하지 않았다.

## 목적

- 데이터를 추가해도 CER 이 개선되지 않는 원인을 데이터 품질 쪽에서 찾는다
- 학습 활용 데이터를 재선별할 근거를 만든다
- 반복되는 결함을 막을 **텍소노미 표기 규칙**을 도출한다

## 3. A. 숫자 표기 불일치 — 1,837행 · 가장 큼

**■ 증상** — 화면에는 콤마가 있는데 정답에는 없다

```
이미지  @1,300      →  정답  1300
이미지  8,800       →  정답  8800
이미지  18,700원    →  정답  18700
이미지  83,636      →  정답  83636
```

![A 숫자 표기](images/03_A_숫자표기.png)

**■ 원인**
- `receipts3000` 은 사내 생성 합성 영수증이다
- 화면에는 `@4,500` 으로 그려놓고, 정답에는 **생성기 내부 값 `4500`** 을 그대로 썼다
- 원본 라벨(`cand_crops/manifest.jsonl`)부터 그렇게 되어 있다

**■ 출처별 콤마 처리 — 규칙이 통일되어 있지 않다**

| 출처 | 숫자 정답 | 콤마 유지 | 경향 |
|---|---|---|---|
| **receipt3000** | 1,883 | **0** | 100% 제거 |
| korie_ocr | 1,476 | 869 | 혼재 (59%) |
| cord | 471 | 314 | 혼재 (67%) |
| korie_kid | 149 | 64 | 혼재 (43%) |

- 같은 태스크 안에서 출처마다 반대다
- `receipt_markdown` 은 콤마를 유지한다 → 같은 영수증인데 태스크마다 규칙이 다르다

**■ 채점 영향 (TEDS 실측)**

```
속성 추가 (frame/rules/width)   TEDS 1.0000
<b> 서식 추가                   TEDS 1.0000
<th> → <td>                     TEDS 1.0000
콤마 제거 4,500 → 4500          TEDS 0.9714   ← 이것만 감점
```

- **숫자 표기만 실제로 점수에 영향을 준다**
- SS 계산서·견적서 오답의 78~83%가 "표기 차이" 인데, 콤마를 떼도록 1,837번 가르친 것이 그중 일부를 만들고 있을 수 있다

**■ 조치 — 제외가 아니라 재생성**

```
지금   gt = 4500        ← 생성기 내부 값
고침   gt = @4,500      ← 화면에 그린 문자열
```

- 이미지는 그대로 두고 정답만 바꾸면 된다. 1,837행이 살아남는다

## 4. D. bbox 와 정답 범위가 어긋남 — 22행

**■ 증상**

```
크롭 이미지   "0051-0"                                    (84×34px)
정답          "[등록] 2020-08-20 13:50 POS: 0051-0"       (33자)
```

- 84×34 픽셀에 33자가 들어갈 수 없다
- 크롭에 **보이지도 않는 글자를 정답으로 학습**하게 된다

![D bbox 불일치](images/04_D_bbox불일치.png)

**■ 더 심한 사례**

| 파일 | 크기 | 글자당 면적 | 정답 |
|---|---|---|---|
| `cand_crawl_google_gcse_00066_40.png` | 13×19px | **2 px²/자** | 이용해 주셔서 감사합니다.\n택시불편민원 신고는 120… |
| `cand_korie_kid_IMG00633_6.png` | 62×21px | 7 px²/자 | 1. Requirements Gathering… |
| `cand_crawl_google_gcse_00006_31.png` | 36×27px | 7 px²/자 | 201280\n004 양피(소) 1망\n2,850… |

**■ 원인 — Layout Detection 출력을 검증 없이 받았다**

```
DocStudio 파서   →  block_bbox 와 block_content 를 짝지어 반환
                     ↑ 여기서 이미 어긋남
build_exp007.py  →  그 짝을 그대로 크롭·정답으로 저장
                     ↑ 검증 없음
```

- 자르는 코드 자체는 맞다. 같은 블록의 좌표로 자르고 같은 블록의 텍스트를 정답으로 쓴다

**■ 사내 다른 스크립트는 이미 이 위험을 막고 있었다**

`crop_blocks.py` 주석

> 텍스트는 붙이지 않는다 — 병합 블록의 텍스트는 이 작은 박스의 텍스트가 아니다.

**■ 조치 — 코드 수정 완료**

`vlm_exp34/scripts/build_exp007.py`

```python
MIN_AREA_PER_CHAR = 55

# 파서가 준 block_bbox 와 block_content 가 어긋나는 경우가 있다.
# 넓은 영역에서 읽은 텍스트를 좁은 박스에 붙여 넘기면, 크롭에는
# 보이지도 않는 글자를 정답으로 학습하게 된다.
if len(gt) >= 6 and (x1-x0)*(y1-y0)/len(gt) < MIN_AREA_PER_CHAR:
    stat[f"{src}:bbox-텍스트 불일치"] += 1
    continue
```

## 10. 텍소노미 규칙에 반영이 필요한 항목

이번 검사에서 **규칙이 없어서 생긴 문제**가 확인되었다. 텍소노미 정의에 포함을 제안한다.

| 항목 | 현재 상태 | 제안 |
|---|---|---|
| 숫자 표기 | 출처마다 콤마 유지/제거가 다름 | **화면에 인쇄된 그대로** 전사 |
| 통화 단위 (`원`) | receipt3000 만 제거 | 화면 그대로 |
| 날짜 형식 | `APR 01, 2015` ↔ `2015-04-01` 혼재 | 화면 그대로 |
| `@` 등 기호 | receipt3000 만 제거 | 화면 그대로 |
| 마크다운 제목(`#`) | 같은 태스크에서 유무 혼재 | 규칙 통일 필요 |
| 크롭 최소 크기 | 하한 없음 | 12px 이상 · 55 px²/자 이상 |

**■ 원칙 제안**

> 파싱·OCR 정답은 **화면에 보이는 그대로** 전사한다.
> 정규화는 정답 단계가 아니라 후처리 또는 채점 기준에서 다룬다.

- 지금은 정답 생성 시점에 정규화가 섞여 들어가, 같은 문서가 태스크마다 다른 정답을 갖는다

## 11. 검사 과정에서 걸렀던 오탐

정확한 판정을 위해 네 번 기준을 고쳤다. 같은 오판을 반복하지 않기 위해 기록한다.

**■ ① `html_table` 5,461행 — "프롬프트 위반" 은 오판**
- 표 프롬프트가 금지한 `<b>` `<sup>` `frame=` 을 100% 쓴다고 봤으나,
  `html_table` 은 **전용 프롬프트 12종**을 쓰고 그중 하나는 오히려
  *"셀 내용과 서식(굵게, 위첨자 등)을 최대한 보존하라"* 고 요구한다

**■ ② 신규 서식 `<th>` 6,435행 — "가장 시급" 도 오판**
- 13,000건 중 49.5%가 `<th>` 없이 `<td>` 만 쓰는 것은 사실이나,
  TEDS 실측 결과 `<th>` ↔ `<td>` 차이로 **1점도 깎이지 않는다**

**■ ③ 크롤링 "라벨 미완성 196건" — 오판**
- 정답 80자 미만 196건 중 **195건이 크롭**이었다. 크롭 정답이 짧은 것은 정상이고 라벨도 정확했다

**■ ④ `C 무관한 문서` 259건 → 1건**
- 정규식 `as follows` 가 **증권취득신고서 양식 문구**에 걸려 256건을 오탐했다
