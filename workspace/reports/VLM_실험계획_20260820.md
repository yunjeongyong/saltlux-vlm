## 1. 측정부터 고친다 (학습 없음)

실험을 더 돌리기 전에 처리한다. 지표가 못 믿을 상태에서 학습을 늘리면 결과를
읽을 수 없다.

### M1. 폭주 억제 설정 확정 — 40분, GPU만

표 크롭 98건에 baseline / stoploop / norep8 을 돌려 TEDS 를 비교한다.
`scripts/repro_runaway.py` 의 대상 필터를 table 로 열면 그대로 쓸 수 있다.

- **판정**: 표 TEDS 열화 없음 → 그 설정을 서빙 기본값으로. norep8 이 표를
  깨면 stoploop 채택(텍스트 3.40 로도 충분히 회복된다).
- **반영처**: `scripts/eval_crops.py` 의 generate 인자, 그리고 사내 서빙 설정.

### M2. 주지표 교체

평균 CER 을 대표값에서 내린다. 폭주 몇 건이 전체를 흔든다.

- 주지표: **완전일치율 · CER 중앙값 · TEDS**
- 보조: 폭주율(CER>1 비율), 상한도달 건수
- 시트에 이미 `CER_중앙값` / `CER>1(폭주)` 컬럼이 있으므로 채우기만 하면 된다.

### M3. eval_loss 비교 금지 명시

train 토큰 p50 이 510 인데 val 은 1,331 이다. 학습셋을 크롭 위주로 바꾸면
분포가 벌어져 eval_loss 가 올라간다 — 모델이 나빠진 게 아니다. exp_005(0.1585)와
exp_006(0.1898)을 직접 비교하면 틀린 결론이 난다. 시트 메모에 못 박는다.

### M4. val/test 분리

두 셋이 같은 이미지를 본다(`vlm_exp34/README.md` 기재). test 를 독립 셋으로
쓰려면 다시 갈라야 한다. 지표 연속성이 끊기므로 실험 사이클 경계에서 한다.

## 2. 학습 실험

### exp_007 — 짧은 타깃 EOS 보강

**가설**: 학습셋에 2~10자 타깃이 부족해 모델이 짧은 출력에서 EOS 를 못 찍는다.

디코딩으로 폭주의 *크기* 는 잡혔지만 *건수* 는 26 → 24 로 거의 안 줄었다.
`합계` 를 `100000000` 으로 읽는 인식 오류 자체는 남아 있고, GT 가 2~4자라
조금만 틀려도 CER 이 1 을 넘는다.

- **선행 조사(학습 0)**: `exp007_all` 50,457행의 타깃 길이 분포. 2~10자 비율이
  평가셋(폭주군 중앙값 9자)에 비해 얼마나 낮은지 확인.
- **처치**: 짧은 타깃 크롭을 보강. 합성 생성기가 어절·줄·블록 4단계 bbox 를
  내므로 짧은 크롭은 추가 라벨링 없이 뽑을 수 있다.
- **성공 기준**: 폭주 건수 26 → 5 이하, 완전일치율 유지 또는 상승.
- **비용**: 조사 1시간 + 학습 1사이클.

### exp_008 — 합성 대 후보 데이터 분리

**가설**: exp_006 의 증량분 39,284행 중 무엇이 효과를 냈는지 모른다.

exp_006 은 자체 합성 14,000 과 외부 후보 25,284 를 한꺼번에 넣었다. 둘의 성격이
전혀 다르므로(합성은 정답이 확정적, 후보는 출처별 품질 편차) 분리해야 다음
사이클에서 어디에 투자할지 정해진다.

- **A**: exp004c 11,173 + 합성 14,000
- **B**: exp004c 11,173 + 후보 25,284
- **비교 대상**: exp_006(둘 다), exp_004(둘 다 없음)
- **비용**: 학습 2회. DDP 가 되면 하루, 안 되면 이틀.

### exp_009 — 평가셋 브랜드 누출 통제

**문제**: 합성 생성기 `gen_synth_receipt2.py:41` 에 평가셋과 같은 브랜드·지점이
들어 있다 — `("emart", "이마트", [... "왕십리점" ...])`. 평가셋 `test_receipt01`
이 `emart 이마트 왕십리점` 이다.

사업자번호·품목·금액은 무작위라 정답 유출은 아니지만, 상호·지점 문자열을
외워서 점수가 오를 여지가 있다. exp_006 이후 성능이 실제 일반화보다 좋게
나올 수 있다.

- **처치**: 평가셋에 등장하는 브랜드를 생성기에서 제외하고 합성 재생성 → 재학습.
- **판정**: 성능이 유지되면 누출 영향 없음. 떨어지면 그 차이가 누출분이다.
- **비용**: 합성 재생성 2시간 + 학습 1사이클.

### exp_010 — 베이스 교체 (Qwen3.8-27B)

8/19 에 받아만 두고 미사용(52G). 위 실험들로 데이터·디코딩이 정리된 뒤에 한다.
지금 바꾸면 변인이 둘이 된다.

## 3. 인프라

| 항목 | 내용 | 상태 |
|---|---|---|
| **DDP** | 파이프라인 병렬은 8장 중 1장만 일한다(util 실측 1~12%). 가중치 65.5GiB 가 H100 한 장에 들어가므로 복제가 맞다. 되면 실험 1회가 38시간 → 5~8시간 | 오늘 밤 스모크 |
| **max_len** | 실제 최대 4,340 인데 8,192 로 잡혀 있다. 4,608 로 내려도 잘림 0 | 다음 실험부터 |
| **VRAM 로깅** | 로그에 실측 메모리가 없어 설정 비교가 추측이 된다. `torch.cuda.max_memory_allocated()` 한 줄 | 즉시 |
| **길이 정렬 배치** | `group_by_length` 가 transformers 5.15 에서 제거됨. p50 510 / 최대 4,340 이 한 배치에 섞이면 패딩 낭비 | DDP 확정 후 |
| **FSDP** | 두 번 실패(LoRA fp32 / 베이스 bf16 불일치). DDP 가 되면 필요 없다 | 보류 |

## 4. 순서와 근거

```
1주차   M1 폭주 설정 확정 ─→ M2 지표 교체 ─→ exp_007 (EOS 보강)
        인프라: DDP 확정, VRAM 로깅, max_len 조정
2주차   exp_008 (합성/후보 분리) ─→ exp_009 (누출 통제)
3주차   M4 val/test 분리 ─→ exp_010 (베이스 교체)
```

**측정을 먼저 두는 이유** — 지금 상태로는 어떤 실험을 해도 평균 CER 로는 판정이
안 된다. M1 은 학습이 없고 40분이면 끝나며, 끝나는 순간 지난 네 실험의 숫자가
전부 다시 읽힌다. 투자 대비 회수가 가장 큰 항목이다.

**exp_007 을 첫 학습 실험으로 두는 이유** — 폭주는 실서비스에서 정확도 몇 %p
문제가 아니라 파싱 실패다. 영수증 합계 필드가 `0` 1,024자로 나오면 그 건은
버려진다. 데이터를 더 붓기 전에 새는 곳을 막는다.
